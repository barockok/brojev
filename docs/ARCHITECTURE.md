# brojev architecture proposal (draft, 2026-10-12)

Inputs: [study-jev-ultrafast.md](study-jev-ultrafast.md), [cdp-capability-matrix.md](cdp-capability-matrix.md) (same folder).

## Principle
Speed comes from Claude delegating whole sub-goals to a Jev loop (about 180 ms per decision), not from faster single clicks. Parity with Playwright/human comes from a second tier of primitive tools that Claude drives directly when Jev cannot. Both tiers share one CDP engine. No Playwright, no extension.

## Process model
```
Claude Code ──stdio──> brojev MCP server (thin, per session)
                            │ local IPC (unix socket)
                            v
                       brojevd (long-lived daemon)
                            │ one CDP WebSocket, held open
                            v
                         Chrome (user profile via chrome://inspect toggle, or dedicated profile)
```
- Daemon holds a single WebSocket so Chrome's "Allow remote debugging?" prompt appears once, not per tool call.
- Connect via `DevToolsActivePort` (port + ws path), not `/json` (404 on toggle route).
- Never pass `--enable-automation`; avoid `Runtime.enable`; run our JS in an isolated world.
- brojev opens its own tabs in its own window (no hidden-tab throttling, no focus stealing).

## Tier 1: `brojev_run` (fast path)
```
brojev_run(goal, url?, values?, files?, expect?, max_steps?) ->
  { status: done|blocked|needs_claude|budget, answer?, page: {url,title,summary}, trace, timings }
```
Loop per step: snapshot -> ONE Jev request (operation question + one target question per operation, options restricted to compatible elements) -> validate freshness -> execute -> minimal wait.

Changes vs jev-ultrafast:
- **Extended operation set** (client-defined, confirmed): CLICK, TYPE_TEXT, SELECT, PRESS_KEY, HOVER, SCROLL (per scroll container), UPLOAD, SWITCH_TAB, DIALOG_ACCEPT/DISMISS, BACK, WAIT, DONE, BLOCKED, ASK_CLAUDE. Parameters always come from fixed-option questions, never generated by Jev.
- **`values` from Claude**: Claude passes field values (`{from: "Zurich", date: "2026-11-20"}`); TYPE_TEXT picks one via a choice question. Helper LLM only when no provided value fits. Saves a model call per field.
- **Dates/numbers in code**: date inputs set directly; calendars resolved by code matching aria-labels to the ISO date; Jev never compares numbers.
- **Confidence gating**: low confidence or repeated stale retries -> return `needs_claude` with current state instead of thrashing (the Sep-20 calendar loop would have stopped in 2-3 steps).
- **Answer on DONE**: an extract step (helper LLM over visible text, or Claude) so the result returns data, not just a status.
- **Budget hit returns a status**, no exception.
- **Element ordering** de-biased (Jev favors first option): order by relevance/position groups, not raw DOM order.

## Tier 2: primitives (parity path, replaces Playwright MCP)
`snapshot` (indexed elements, refs), `act(op, ref, value)`, `click_xy` / `drag_xy` / `scroll_xy`, `key(combo)`, `type(text)`, `screenshot`, `eval` (opt-in), `tabs` (list/open/switch/close), `upload(ref, paths)`, `dialog(accept|dismiss, text?)`, `downloads`, `wait(for: text|url|network-idle|selector, timeout)`, `cookies/storage` save+restore, `emulate` (viewport, geo, tz, permissions), `pdf`.
Claude uses these when `brojev_run` returns `needs_claude`/`blocked`, then may call `brojev_run` again to resume.

## CDP engine (shared)
- Hand-rolled Go CDP client on `coder/websocket`, types from `cdproto`. Every command has a timeout.
- `Target.setAutoAttach {flatten:true}` for popups and OOPIF; per-frame sessions; frame-offset chain for click coordinates.
- Snapshot: one isolated-world evaluate per frame; pierces open shadow roots; includes clickable non-semantic elements (cursor:pointer, onclick, role); offscreen elements summarized rather than dropped.
- Actionability (visible, stable, enabled, hit-test multiple points, editable) checked cheaply before input.
- Dialog, file chooser, download handlers run as event listeners outside the command flow.
- Keyboard: port Playwright's US layout + `macEditingCommands` tables to Go (Apache-2.0, attribute).
- Network-idle via our own in-flight counter.
- Canvas / non-DOM UI: screenshot + coordinates via Tier 2.

## Things CDP cannot do -> handled by
Native select/date/color popups: set value via JS. OS file pickers (`showOpenFilePicker`): override function. Permission bubbles: pre-grant. Browser chrome shortcuts: Target domain. Captchas: hand to the human, no solver services. Full list in the matrix doc.

## Verification
- Fixture suite (local pages, offline): forms, shadow DOM, same-site + cross-site iframes, popups, all dialog types, uploads, downloads, drag-and-drop, hover menus, nested scroll, contenteditable, canvas, mac shortcuts. Each runs through Tier 2 and, where expressible, Tier 1.
- Live task set with independent checkers (future dates computed at runtime, never hardcoded).
- Benchmark: same tasks vs Playwright MCP (wall time, tokens, success).

## Milestones
- M0: CDP client + daemon + connection (toggle and dedicated profile). Doctor command.
- M1: snapshot + Tier 2 primitives, fixture suite green.
- M2: Tier 1 Jev loop with extended ops, values, gating, answers.
- M3: plugin packaging (MCP server, skill with routing rules, install docs).
- M4: benchmark vs Playwright MCP; GEPA tuning of goal phrasing, option labels and skill routing.

## Decisions (2026-10-12, user)
1. **Language: Go.** Single static binary `brojev` with subcommands `daemon`, `mcp`, `doctor`, `run`.
   Deps: `github.com/coder/websocket` (CDP transport), `github.com/chromedp/cdproto` (generated protocol types only, not a driver), `github.com/modelcontextprotocol/go-sdk` (MCP stdio). TypeSafe client hand-rolled (no Go SDK; one POST endpoint).
   Note: Go does not cut per-step latency much (Jev ~180 ms + Chrome dominate); wins are startup, concurrency, zero-runtime install.
2. **Default browser: dedicated profile.** Daemon launches headed Chrome with `--user-data-dir=~/.brojev/profile --remote-debugging-port=0` (allowed on non-default profiles), reads DevToolsActivePort. User logs in to sites once in that profile. Real-profile attach (chrome://inspect toggle) is a later opt-in flag.
